## UX-001：选文件后，接收目标与发送按钮禁用原因不明确

- **报告日期/环境**：2026-10-29，真实 Windows 修复包 `671a79e`；Mac 配合反向验收。
- **实际场景**：用户 Choose files 选好了文件，但没有选中 Nearby Devices 中的 Mac，
  Send files 保持灰色。列表还显示两个 Smoke 测试条目，用户没有意识到需要另选目标。
  单击已配对 Mac 设备行后成功发出请求，Mac 实际收到正确 37 B 文件并接受。
  Windows 界面情况由所有者报告，没有 Windows 截图。
- **设计问题**：文件选择与目标选择的关系不明显；按钮禁用缺少就地解释；
  多条设备记录中，哪些可用、哪台是当前发送目标，缺少足够清晰的引导。
- **M9 需要由所有者设计/决定**：文件与接收目标的布局、目标选择反馈、禁用原因提示，
  以及多设备/未配对/测试记录混杂时的呈现。单个已配对在线设备在主窗口是否默认选中，
  留作设计决策，本轮不提前改变行为。
- **验收标准**：用户不依赖额外口头指导即可知道当前目标、下一步和按钮不可用的原因；
  单目标、多目标、未配对、掉线、键盘操作及两端显示均清楚，不会静默发送到错误设备。
- **既有约束**：保留双方配对和逐次收件确认；文件管理器已有“单个合格目标直发、
  多目标选一次即发”流程继续有效。发现记录是否正确过期/清理另按实证核验，
  不通过简单按 Smoke 名称过滤来掩盖问题。
- **当前状态**：已记录，等待 M9 设计；本次没有修改界面或自动选择逻辑。
