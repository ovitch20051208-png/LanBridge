## M7：剩余测试按四轮执行

| 顺序 | 测试内容 | 必须看到的结果 |

| 7A：Windows 接收端异常 | 专用目录不可写、小容量虚拟盘接收前空间不足、实际传输中强制结束、重启清理和重传。 | 双方明确失败，原文件保留；失败/重启时按预期清理暂存；恢复目录后重传哈希一致。 |

| 7C：原生入口与连接边界 | 快速连续调用 Finder / Send To，冷/热启动和单实例，不同目录同名文件、设备改名、组播不可用时手动连接。 | 文件和目标正确、没有无关第二实例、原文件保留且输出校验正确；测试后恢复发现与设置。 |
| 7D：剩余可靠性问题 | 在专用虚拟盘安全验证传输中空间耗尽、约定的连续/重复传输，以及此前非致命 asyncio 退出日志。 | 有完整成功/哈希或明确失败/清理证据；基线签字前定位并处理已知故障，不通过屏蔽日志宣称解决。 |

## M8：冻结前需要留下什么

1. 明确 V1 范围、必测清单结果、经你同意的环境延期项、已知功能 Bug 已关闭的记录。
   较早的 asyncio 退出日志也须有解决证据或经明确复核的处理结论。
2. 不依赖 Python 的干净/非管理员原生安装、固定位置、入口安装/重装/移除，
   更新保留身份/配对/设置，卸载保留用户状态和已收文件。
3. 两端真实注销再登录：先开启登录启动验证后台接收，再关闭后重新登录验证不启动。
   只检查 LaunchAgent / Run 注册项不算完成。
4. 全量检查、准确源码对应的 CI 原生构建/打包自检，以及这些包的最终双向实机冒烟。
   CI 产物只保留 14 天，须提前独立保存安装包和 SHA-256；tag 本身不保存安装包。
5. 源码 SHA、包内构建信息、系统/架构、证据与剩余发行前置条件。
   私钥、完整用户配置、签名秘密和构建缓存不提交到 Git。

拟用带说明的 tag：`baseline/pre-uiux-v0.1.0`。
它固定“已验收的开发预览功能基线”，不表示已正式发行或完成签名。
等 M8 通过后才确定实际 commit，不把今天的版本提前称为冻结完成。

## M9：UI/UX 分支与回归约束

拟用分支：`uiux/desktop-redesign`，进入 M9 时从 M8 的 tag 创建。
改版期间 `main` 保留已验收功能基线。每个独立 UI 模块验证后建立清晰 commit，
**立即推送到 UI 分支**；最后整体验收后才合并到 `main`。
该阶段首先补齐分支 CI：目前只有 `main` push 做原生构建，PR 只有测试、没有构建，
不能因为开了分支就假定分支包已经验证。

先定流程/线框与共同设计规则，再依次做：设备列表与待发文件、收件确认、传输
状态/历史、设置与接收目录、托盘/菜单栏及平台入口。
每个模块检查 Mac 与 Windows 的键盘焦点、高 DPI/窗口大小、长路径/中文、浅色/深色，
再同步中英文指南和真实截图。

保留已验收操作：普通重开保留文件且不自动发；右键入口只有一个已配对在线目标
就直接请求，多目标选一次即发；接收方逐次确认；关窗口仍接收、Quit 才停止；
原文件不覆盖、SHA-256 校验后才 complete；完成任务能归档/回看。
开发/自动化用隔离配置，最终原生单实例验收用正常用户配置。
TLS、证书固定和双方配对确认始终保留。

改版后重跑：双向小文件/多文件/空文件/中文/同名/4 GiB，拒绝/超时/取消/断网/
重启清理，冷/热启动右键入口、隐藏主窗口收件、设置与真实登录行为。
改版前的通过记录不能替代改版后的验证，回归修复完成才合并。

## 回退与改版期间的功能修复

- 保留基线 tag 和成功安装包；失败尝试留在独立分支/commit，需要时使用基线包继续工作。
- M9 发现功能问题，先在 `main` 修复、验证并立即推送，再合入 UI 分支复测。
- 已发布修改用 `git revert` 回退，切换前保护未提交改动；不 force-push，不重写发布历史。
- 本规划不增加移动端、云中转、自动接受、文件夹传输或断点续传；新功能另行确定范围。

参见[开发与 Git 工作流](DEVELOPMENT.md)和[安全边界](SECURITY.md)。
